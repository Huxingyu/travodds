## 硬件与依赖

以下是开发建议，并非已测得的最低门槛：

| 场景 | CPU | 内存 | 空闲磁盘 |
|---|---|---|---|

## 复现构建

```bash
# 在具有上述依赖的 Linux 上，位于仓库根目录执行：
CMAKE_BIN=cmake BUILD_JOBS=1 bash tools/ospp/bootstrap.sh /absolute/path/to/travodds-output

  --build-root /absolute/path/to/travodds-output \
  --output /absolute/path/to/travodds-output/results/smoke

  --output-on-failure --parallel 1 --timeout 45

  --output-on-failure --parallel 1 --timeout 45
```

安装仅进入指定输出目录的 `install/`，无需 sudo。测试串行运行，避免多个测试进程使用相同 DDS domain/topic 时互相干扰。构建脚本不自动运行测试；构建成功与测试成功分别记录。

## 运行参数

现有示例使用 Domain ID `114`、Topic `topic`、`HelloWorld` 类型，双方必须一致。`hello_world` 默认同时启用 UDPv4 与 SHM，不能用它单独证明 UDP 数据路径。`transmit_shm` 显式移除 UDPv4 并启用 SHM。`tools/ospp/udp_example.py` 额外生成 `udp_only` 变体，显式移除 SHM，且不修改上游示例文件。最小双进程测试在同一主机/容器完成，无需公网端口或外部服务。

SHM 双方需要访问同一个共享内存命名空间，`/dev/shm` 需要可写且容量足够。当前示例的这些参数写在源代码中，没有统一运行配置文件；本次无需编写 XML。未来 DataSharing 的开关、目录、类型约束、池容量、回收策略和回退规则仍需实现、设计与确认，当前不能把它们作为已可配置功能。

## 当前内存池实现

1. `IPayloadPool` 抽象载荷分配与归还；现有 `MemoryPool` 实现该接口。
2. `ITopicPayloadPool`、四种普通内存策略和弱引用注册表已经实现。按 domain/topic/type 分享兼容配置的池，不兼容配置明确报错。
3. 普通用户 Writer 的序列化载荷已使用注册的动态复用 Topic 池。动态元数据按需增长，归还操作不申请内存。当前保持旧池的 uint32 容量上限，单个 Writer 的历史资源限制仍由 history/resource_limits 管理；四策略的公开 QoS 选择待接入。
4. `PayloadBufferPtr` 在写入准备阶段保管缓冲链。部分分配失败、序列化返回错误或抛异常时自动回收；成功后转交 `CacheChange`。缓存持有原池，析构时归还每个载荷并删除本地描述符。
5. `Writer::NewChange` 支持显式原池；内置发现保留旧池默认值。用户 Writer 的注销/dispose 控制缓存也指定其原池，键注册等独立缓冲仍使用旧池。
6. 六种 Reader take 路径不再直接归还复制描述符中的全局池指针；缓存引用保活到读取结束。历史读取同时更新样本计数、唤醒空间等待者，并移除可能存在的总索引引用。常规 Reader AddChanges 路径与使用总索引的 HistoryCache::AddChange 路径分别验证。
7. CMake 显式要求 C++17，包含对齐分配所需的语言支持。

这些能力仍属于普通池与所有权基础设施。共享段、跨进程通知、DDS Loan、发现协商、QoS/XML 和序列化旁路尚未实现；不能据此宣称端到端零拷贝。一个缓存的缓冲链要求来自同一池，描述符仍是进程内对象。新接口改变内部类布局，库与依赖方需要一起重编译。

## 多 Writer 共享实例的 deadline 生命周期（2026-10-27，本阶段通过）

两个新增确定性回归在前一阶段已验证的库上均失败：SHARED 所有权下，一个 Writer 发出 unregister 就停掉整个实例的 requested deadline；最后一个 Writer 消失时，实例却保留活动 deadline。现在 Reader 按 history 中的实际实例状态更新期限：ALIVE 样本刷新，生命周期控制在实例非 ALIVE 时暂停；若其他 Writer 仍使实例存活，则保留原期限，不把 unregister 当成新数据刷新。RemoveRemoteWriter 在移除最后一个 Writer 时清除该实例期限。

回归在可靠和尽力 Reader 下分别验证两个 Writer 对同一键的 ALIVE、一个 Writer 退出后原期限保持、到期通知，以及最后一个退出后不再通知。样本来自独立的真实共享池，经已匹配端点的 SubmitDataChange 提交；注销通过控制缓存提交，Writer 消失直接调用 history 的 RemoveRemoteWriter。它们验证接收/状态逻辑，不代替独立进程崩溃、发现租约或重启的故障验收。

- 最终普通与独立 ASan/UBSan 版各 **247+142+22=411 项**通过，核心耗时分别 **254.446 秒**和 **257.4 秒**；无检查器诊断，仍关闭 LeakSanitizer。

新增确定性回归构造定时器已读到到期实例、接收路径随后处理 dispose/unregister 或最后一个 Writer 消失、旧回调再尝试更新期限的顺序。旧库的同一用例在四种状态变化中均会重新启用已非 ALIVE 的实例；修复前 1 项失败，修复后连同原有 20 项针对性测试全部通过。
